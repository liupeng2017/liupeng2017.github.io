Pixso（最新项目产品）

最新的项目产品是 Pixso，一款在线协作的 UI 设计与交付工具，覆盖从画布绘制、设计规范到研发交接的完整链路。下面按组件、组件库、变量、文本、布局、渲染六个重点各配一张官方站点截图说明。

组件

组件把可复用的界面单元（按钮、头像、导航栏等）做成母版，页面里放的是它的实例。颜色与按下、松开等状态共同组成组件变体，实例通过属性面板选择对应组合，不用为每个状态单独画一份。

尺寸为不同场景、内容为长标题或不同按钮文案，都可以用变体组织尺寸与状态，再用文本、图层可见性和实例交换属性控制内容；配合自动布局，按钮会随文案长短自动伸缩，列表会随条目增减自动重排。为默认、悬停、禁用、加载、错误和成功状态建立变体，是组件在真实产品里的主要用法。

组件库

样式用于复用成组的视觉属性——颜色、文本、效果和布局网格集中管理，改一次定义，所有引用它的图层同步更新。基础样式与可复用组件在同一份设计文件中维护。

组件和样式可以发布为团队资源库，其他设计文件启用后即可复用，更新由团队有序接收——不是静默覆盖，而是接收方按需同步，避免正在改的稿子被突然刷新。

变量

变量用来管理可重复使用的值：用颜色、数值、文本和布尔变量组织属性值，把尺寸、间距、圆角或主题变化落实到图层。数值变量一套就能驱动间距和圆角，布尔变量控制显隐与开关态，文本变量切换多语言文案，颜色变量挂上主题模式后浅色、深色一键切换。

文本

文本样式把字号、行高、字重成组复用，保证标题、正文、辅助说明在各页面保持一致。团队可以统一字体和字重，减少换设备后出现的排版差异。

可变字体在一个字体文件里连续调节字重，从细体到加粗不再依赖多个字重文件，排版更细腻，也更容易和变量、文本样式配合做统一的文字规范。

布局

自动布局让内容决定排列：设置方向、间距、内边距与尺寸规则后，容器随内容增减自动扩展，条目按规则对齐，不必手动挪像素。做响应式卡片、工具条、列表时最省事。

布局网格也可以作为样式复用，把列数、间距、边距定成规范，多个页面共享同一套栅格。

渲染

设计稿进入研发阶段后靠渲染输出：交付模式里查看所选图层的属性、间距标注与盒模型，并拿到参考的样式代码，实现可以直接照抄数值。

资源按需批量导出 PNG、SVG 等格式与倍率，背景与切图设置都在属性面板里完成，一次配置输出多个尺寸。设计稿中的布局、样式与资源可以转换为前端实现的起点，减少来回截图、猜间距的沟通成本。

HBITMAP CShowBmpInDlgDlg::CopyScreenToBitmap(LPRECT lpRect)
{
//lpRect 代表选定区域
{
HDC hScrDC, hMemDC;
// 屏幕和内存设备描述表
HBITMAP hBitmap, hOldBitmap;
// 位图句柄
int nX, nY, nX2, nY2;
// 选定区域坐标
int nWidth, nHeight;
// 位图宽度和高度
int xScrn, yScrn;
// 屏幕分辨率
 
// 确保选定区域不为空矩形
if (IsRectEmpty(lpRect))
return NULL;
//为屏幕创建设备描述表
hScrDC = CreateDC(“DISPLAY”, NULL, NULL, NULL);
//为屏幕设备描述表创建兼容的内存设备描述表
hMemDC = CreateCompatibleDC(hScrDC);
// 获得选定区域坐标
nX = lpRect->left;
nY = lpRect->top;
nX2 = lpRect->right;
nY2 = lpRect->bottom;
// 获得屏幕分辨率
xScrn = GetDeviceCaps(hScrDC, HORZRES);
yScrn = GetDeviceCaps(hScrDC, VERTRES);
//确保选定区域是可见的
if (nX<0)
 
nX = 0;
if (nY<0)
nY = 0;
if (nX2>xScrn)
nX2 = xScrn;
if (nY2>yScrn)
nY2 = yScrn;
nWidth = nX2 - nX;
nHeight = nY2 - nY;
// 创建一个与屏幕设备描述表兼容的位图
hBitmap = CreateCompatibleBitmap
(hScrDC, nWidth, nHeight);
// 把新位图选到内存设备描述表中
hOldBitmap =(HBITMAP)SelectObject(hMemDC, hBitmap);
// 把屏幕设备描述表拷贝到内存设备描述表中
BitBlt(hMemDC, 0, 0, nWidth, nHeight,
hScrDC, nX, nY, SRCCOPY);
//得到屏幕位图的句柄
hBitmap = (HBITMAP)SelectObject(hMemDC, hOldBitmap);
 
//清除
DeleteDC(hScrDC);
DeleteDC(hMemDC);
// 返回位图句柄
return hBitmap;
}
}

HarmonyOS 应用开发者高级认证备考笔记

2026-11-02

这篇是把 HarmonyOS 应用开发者高级认证（理论考试）的备考内容压缩成一页能过完的版本：十组必背对比、四条生命周期、35 条高频易错判断、自编自测 12 题。考试规则以华为开发者学堂官方页面为准。

考试信息
项目 数值
时长 60 分钟
满分 / 及格 100 / 80
考试次数 每月 3 次
形式 在线客观题（判断 / 单选 / 多选）
前置 实名认证

及格线是 80 分，多选题通常分值更高且少选错选都不给分，所以别空题，也别说”多选我只敢选一个”——那是策略，不是妥协。

一、ArkTS 与 TypeScript 的差异（禁用清单）

ArkTS 为了编译期能确定对象布局、便于 AOT，砍掉了 TypeScript 里一大票动态特性。这一节几乎每年必考，判断题直接命中。

替代方案记住四个词：明确类型、联合类型、泛型、Map。类型兼容要用名义类型，即显式 implements / extends，光长得一样不算。

二、@State / @Prop / @Link
装饰器 数据源 方向 一句话
@State 组件自身 自身 ↔ UI 私有状态，只观察第一层
@Prop 父组件 父 → 子单向 子组件改了不回传，对象是深拷贝
@Link 父组件 父 ↔ 子双向 父用 $ 传引用，子不能本地初始化

延伸三个：跨层级用 @Provide + @Consume（双向）；观察嵌套对象用 @Observed + @ObjectLink；变化监听 V1 用 @Watch、V2 用 @Monitor。

Storage 一族按作用域记：AppStorage 是应用级内存，PersistentStorage 是应用级持久化，LocalStorage 是页面级。带 Link 的双向，带 Prop 的单向。

三、状态管理 V1 → V2 对照
V1 V2
@Component @ComponentV2
@State @Local
@Prop @Param（配 @Once）
@Link @Param + @Event
@Provide / @Consume @Provider / @Consumer
@Observed + @ObjectLink @ObservedV2 + @Trace
@Watch @Monitor
— @Computed（有缓存，依赖变了才重算）

硬规则：V1 和 V2 不混用。@Param 是只读的，想改就得通过 @Event 回调父组件，这是 V2 的单向数据流。

四、TaskPool 与 Worker
对比 TaskPool Worker
级别 任务级 线程级
线程管理 自动 手动
适合 短时、独立、CPU 密集 长时、常驻、频繁通信
装饰器 @Concurrent —
通信 参数 / 返回值 postMessage / onmessage
数量 由任务池调度，优先级 HIGH/MEDIUM/LOW API 12+ 最多 64 个，旧版 8 个

两者共同点：都是 Actor 模型，内存隔离，都不能更新 UI（UI 只在主线程改）。

@Concurrent 修饰的函数四条限制：不能用闭包变量、不能用 this、不能操作 UI、参数和返回值要可序列化。跨线程共享对象用 @Sendable，普通对象默认是序列化拷贝，不是共享引用。

五、HAR、HSP、HAP
对比 HAR HSP
类型 静态共享包 动态共享包
共享时机 编译时打进 HAP 运行时共享
能否独立安装运行 否 否
典型用途 公共组件、工具 多 HAP 复用、压包体积

依赖关系一张图：

.app 用于上架，.hap 用于安装运行；两种共享包都不能独立跑。

六、router 与 Navigation
对比 router Navigation
官方态度 旧方案，新应用不推荐 推荐
页面栈 系统管理 NavPathStack
页面载体 @Entry NavDestination
多端 较弱 支持 Stack / Split / Auto 分栏
系统路由表 不支持 支持（router_map.json）

题干出现”推荐”就选 Navigation。

七、数据存储选型
方案 类型 分布式 场景
Preferences 轻量键值 否 少量配置、开关、token
RDB 关系型（SQLite） 否 复杂查询、事务、大量结构化数据
KV Store 键值数据库 是 跨设备键值数据
分布式数据对象 内存对象 是 多设备实时协同

两个细节：Preferences.put() 之后要 flush() 才落盘；RDB 的 ResultSet 用完要 close()。

对比 Stage FA
核心单元 UIAbility / ExtensionAbility Ability / AbilitySlice
是否推荐 是 否
窗口 WindowStage AbilitySlice 栈

启动模式默认是 singleton（重复拉起复用实例并触发 onNewWant），其余还有 multiton、specified。

九、自适应布局与响应式布局
类型 手段
自适应布局 拉伸、均分、占比、缩放、隐藏
响应式布局 断点、栅格、媒体查询、资源限定词

断点必背：sm 320–599 / md 600–839 / lg 840–1439 / xl ≥ 1440（vp）；栅格默认 12 列；长度用 vp、字体用 fp。

一次开发多端部署是三层架构：UI 层 + 功能层 + 基础层，不是”一套布局到处拉伸”。

十、权限类型
类型 授予方式 示例
system_grant 安装时自动授予，只需声明 INTERNET、KEEP_BACKGROUND_RUNNING

user_grant 三步：声明 → 填 reason / usedScene → requestPermissionsFromUser。光声明不会自动授权。

背景

常用单例之间操作相互依赖或者对同一份资源进行操作。进行对象或资源释放时候，很容易重复，导致程序异常。

依赖顺序

// a.cpp
static A a;  // 第1个构造 → 最后释放
static LateDestructor late;  // 依赖a，会后析构

// b.cpp
static B b;  // 构造顺序依赖链接顺序 → 释放顺序不确定

// main.cpp
void foo() {
    static C c;  // 在foo()首次调用时构造 → 在main.cpp其他静态变量之后释放
}

int main() {
    foo();
    static D d;  // 构造顺序较晚 → 释放顺序较早
    return 0;
}
释放顺序：d → c → a → b（b的顺序不确定）
